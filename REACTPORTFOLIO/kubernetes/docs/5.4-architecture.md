## Composants du Control Plane

### API Server (kube-apiserver)
- Point d'entree unique du cluster
- Expose l'API REST Kubernetes
- Valide et configure les objets (pods, services, etc.)
- Interface entre les composants et etcd

### etcd
- Base de donnees distribuee cle-valeur
- Stocke l'etat complet du cluster
- Source unique de verite
- Supporte la haute disponibilite (consensus Raft)

### Scheduler (kube-scheduler)
- Assigne les pods aux noeuds
- Prend en compte : ressources, contraintes, affinites
- Algorithme de scoring pour choisir le meilleur noeud

### Controller Manager (kube-controller-manager)
- Boucle de controle qui surveille l'etat du cluster
- Contient plusieurs controllers :
  - **ReplicaSet Controller** : maintient le nombre de replicas
  - **Deployment Controller** : gere les rolling updates
  - **Node Controller** : surveille la sante des noeuds
  - **Job Controller** : gere les taches ponctuelles

## Composants des Worker Nodes

### kubelet
- Agent qui s'execute sur chaque noeud
- Communique avec l'API Server
- Demarre/arrete les conteneurs via le container runtime
- Rapporte l'etat des pods au control plane

### kube-proxy
- Gere les regles reseau sur chaque noeud
- Implemente les Services Kubernetes
- Repartit le trafic vers les pods (iptables/IPVS)

### Container Runtime
- Execute les conteneurs (containerd, CRI-O)
- Interface via CRI (Container Runtime Interface)
- Docker n'est plus supporte directement (depuis K8s 1.24)
