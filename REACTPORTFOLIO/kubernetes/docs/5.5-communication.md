# 5.5 Communication interne et externe du cluster

## Communication interne

### DNS interne (CoreDNS)

Kubernetes fournit un serveur DNS interne qui resout automatiquement les noms de services.

Format de resolution :
```
<service-name>.<namespace>.svc.cluster.local
```

Dans notre projet :
```
frontend-service.portfolio.svc.cluster.local  → pods frontend
backend-service.portfolio.svc.cluster.local   → pods backend
mongo-service.portfolio.svc.cluster.local     → pod mongo
```

### Communication Pod-to-Pod

- Chaque pod a une IP unique dans le cluster
- Les pods du meme noeud communiquent via le bridge reseau
- Les pods de noeuds differents communiquent via le CNI (Container Network Interface)
- Plugins CNI : Calico, Flannel, Weave, Cilium

```
Pod A (10.244.1.5) ──── CNI Plugin ──── Pod B (10.244.2.8)
     Node 1                                  Node 2
```

### Communication Pod-to-Service

Les Services fournissent une IP virtuelle stable (ClusterIP) :

```
Backend Pod ──▶ mongo-service (ClusterIP: 10.96.0.15) ──▶ MongoDB Pod
                        │
                  kube-proxy (iptables/IPVS)
                  repartit vers les pods
```

## Communication externe

### NodePort

Expose le service sur un port statique de chaque noeud :

```
Internet ──▶ Node IP:30080 ──▶ Service ──▶ Pods
```

### LoadBalancer

Cree un load balancer externe (cloud providers) :

```
Internet ──▶ Cloud LB (IP publique) ──▶ Service ──▶ Pods
```

### Ingress Controller

Point d'entree HTTP/HTTPS unique avec routage L7 :

```
Internet
    │
    ▼
┌──────────────────────────────────────┐
│         Ingress Controller            │
│            (nginx)                    │
│                                      │
│  portfolio.local/     → frontend:80  │
│  portfolio.local/api  → backend:5000 │
└──────────────────────────────────────┘
```

### Communication externe dans notre projet

```
┌──────────┐     ┌───────────────┐     ┌──────────────┐     ┌──────┐
│ Navigateur│────▶│    Ingress    │────▶│   Service    │────▶│ Pods │
│ (client)  │     │  Controller   │     │  (ClusterIP) │     │      │
└──────────┘     └───────────────┘     └──────────────┘     └──────┘

  HTTP/HTTPS         Routage L7         Load Balancing      Application
  port 80/443       path-based          round-robin
```

## Network Policies

Les NetworkPolicies controlent le trafic entre les pods :

```yaml
# Seul le backend peut acceder a MongoDB
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: mongo-access
spec:
  podSelector:
    matchLabels:
      app: mongo
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: backend
      ports:
        - port: 27017
```

## Resume des flux reseau

| Source | Destination | Mecanisme | Port |
|--------|------------|-----------|------|
| Internet | Frontend | Ingress → Service | 80 |
| Internet | Backend API | Ingress → Service | 5000 |
| Frontend pods | Backend pods | Service ClusterIP | 5000 |
| Backend pods | MongoDB | Headless Service | 27017 |
| kubectl | API Server | HTTPS | 6443 |
