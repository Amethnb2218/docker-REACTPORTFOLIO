# 5.8 Demo - Integration Kubernetes dans le projet fil rouge

## Objectif

Deployer l'application Portfolio (React + Express + MongoDB) sur un cluster Kubernetes local en utilisant tous les concepts presentes.

## Prerequis

- Docker Desktop avec Kubernetes active (ou Minikube)
- kubectl installe et configure
- Images Docker du projet buildees

## Etape 1 : Preparer les images Docker

```bash
cd C:\Users\khadjia\Desktop\docker\REACTPORTFOLIO

# Build des images
docker build -t portfolio-frontend ./reactportfolio
docker build -t portfolio-backend "./EXPRESSJS PORTFOLIO"

# Verification
docker images | grep portfolio
```

Si Minikube :
```bash
minikube image load portfolio-frontend:latest
minikube image load portfolio-backend:latest
```

## Etape 2 : Creer le Namespace

```bash
cd kubernetes

kubectl apply -f namespace.yaml

# Verification
kubectl get namespaces | grep portfolio
```

**Concept illustre** : Namespace = isolation logique des ressources

## Etape 3 : Deployer les ConfigMaps et Secrets

```bash
kubectl apply -f configmap.yaml
kubectl apply -f secret.yaml

# Verification
kubectl get configmap -n portfolio
kubectl get secret -n portfolio

# Voir le contenu de la configmap
kubectl describe configmap portfolio-config -n portfolio
```

**Concepts illustres** : ConfigMap (config non-sensible), Secret (donnees sensibles en base64)

## Etape 4 : Deployer MongoDB (StatefulSet + Volume)

```bash
kubectl apply -f mongo-pv.yaml
kubectl apply -f mongo-statefulset.yaml

# Attendre que MongoDB soit pret
kubectl wait --for=condition=ready pod -l app=mongo -n portfolio --timeout=120s

# Verification
kubectl get statefulset -n portfolio
kubectl get pvc -n portfolio
kubectl logs mongo-0 -n portfolio | tail -5
```

**Concepts illustres** : StatefulSet, PersistentVolume, PersistentVolumeClaim, Headless Service

## Etape 5 : Deployer le Backend (Deployment + Service)

```bash
kubectl apply -f backend-deployment.yaml

# Attendre
kubectl wait --for=condition=ready pod -l app=backend -n portfolio --timeout=60s

# Verification
kubectl get deployment backend -n portfolio
kubectl get pods -l app=backend -n portfolio
kubectl get svc backend-service -n portfolio

# Tester la connexion interne
kubectl run curl-test --image=curlimages/curl -it --rm -n portfolio -- \
  curl -s http://backend-service:5000/api/projects
```

**Concepts illustres** : Deployment, ReplicaSet (2 replicas), Service ClusterIP, readiness/liveness probes

## Etape 6 : Deployer le Frontend (Deployment + Service)

```bash
kubectl apply -f frontend-deployment.yaml

# Attendre
kubectl wait --for=condition=ready pod -l app=frontend -n portfolio --timeout=60s

# Verification
kubectl get deployment frontend -n portfolio
kubectl get pods -l app=frontend -n portfolio
```

**Concepts illustres** : Deployment multi-replicas, Service ClusterIP

## Etape 7 : Configurer l'Ingress

```bash
# S'assurer que l'Ingress Controller est installe
kubectl get pods -n ingress-nginx

kubectl apply -f ingress.yaml

# Verification
kubectl get ingress -n portfolio
kubectl describe ingress portfolio-ingress -n portfolio
```

Ajouter dans `C:\Windows\System32\drivers\etc\hosts` (en admin) :
```
127.0.0.1 portfolio.local
```

**Concept illustre** : Ingress = routage HTTP/HTTPS externe avec rules path-based

## Etape 8 : Appliquer le HPA et les Network Policies

```bash
kubectl apply -f hpa.yaml
kubectl apply -f networkpolicy.yaml

# Verification
kubectl get hpa -n portfolio
kubectl get networkpolicy -n portfolio
```

**Concepts illustres** : HorizontalPodAutoscaler, NetworkPolicy (securite reseau)

## Etape 9 : Acceder a l'application

```
http://portfolio.local        → Frontend (React SPA)
http://portfolio.local/api    → Backend (Express API)
```

Alternative avec port-forward :
```bash
kubectl port-forward svc/frontend-service 3000:80 -n portfolio
# Acceder a http://localhost:3000
```

## Demonstrations des fonctionnalites K8s

### Demo 1 : Self-healing

```bash
# Voir les pods
kubectl get pods -n portfolio

# Supprimer un pod backend (il sera recree automatiquement)
kubectl delete pod -l app=backend -n portfolio --wait=false

# Observer la recreation
kubectl get pods -n portfolio -w
```

### Demo 2 : Scaling manuel

```bash
# Scaler le backend a 4 replicas
kubectl scale deployment backend --replicas=4 -n portfolio

# Observer
kubectl get pods -l app=backend -n portfolio -w

# Revenir a 2
kubectl scale deployment backend --replicas=2 -n portfolio
```

### Demo 3 : Rolling Update

```bash
# Modifier une variable d'env (simule une nouvelle version)
kubectl set env deployment/backend VERSION=v2 -n portfolio

# Observer le rolling update
kubectl rollout status deployment/backend -n portfolio
kubectl get pods -n portfolio -w

# Voir l'historique
kubectl rollout history deployment/backend -n portfolio
```

### Demo 4 : Rollback

```bash
# Rollback a la version precedente
kubectl rollout undo deployment/backend -n portfolio

# Verification
kubectl rollout status deployment/backend -n portfolio
```

### Demo 5 : Monitoring et logs

```bash
# Etat complet
kubectl get all -n portfolio

# Logs en temps reel
kubectl logs -f -l app=backend -n portfolio

# Evenements
kubectl get events -n portfolio --sort-by='.lastTimestamp'

# Ressources
kubectl top pods -n portfolio
```

## Nettoyage

```bash
./deploy.sh down

# ou
kubectl delete namespace portfolio
kubectl delete pv mongo-pv
```

## Mapping Docker Compose → Kubernetes

| Docker Compose | Kubernetes | Fichier |
|---------------|-----------|---------|
| `services.frontend` | Deployment + Service | frontend-deployment.yaml |
| `services.backend` | Deployment + Service | backend-deployment.yaml |
| `services.mongo` | StatefulSet + Service | mongo-statefulset.yaml |
| `volumes` | PV + PVC | mongo-pv.yaml |
| `environment` | ConfigMap + Secret | configmap.yaml, secret.yaml |
| `ports` (expose) | Ingress | ingress.yaml |
| `networks` | NetworkPolicy | networkpolicy.yaml |
| `depends_on` | readinessProbe | dans les deployments |
| (aucun equivalent) | HPA | hpa.yaml |
