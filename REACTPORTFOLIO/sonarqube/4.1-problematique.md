# 4.1. Problématique — Pourquoi SonarQube ?

## Le constat

Dans un projet comme notre portfolio React + Express, plusieurs problèmes surviennent sans outil d'analyse de code :

1. **Accumulation de dette technique** : Le code non revu accumule des mauvaises pratiques qui deviennent coûteuses à corriger plus tard.

2. **Bugs silencieux** : Certains bugs ne se manifestent qu'en production (null references, conditions mortes, fuites mémoire).

3. **Vulnérabilités de sécurité** : Sans analyse statique, des failles (injection, XSS, dépendances vulnérables) passent inaperçues.

4. **Incohérence du code** : Sans règles partagées, chaque développeur code différemment, rendant la maintenance difficile.

5. **Absence de métriques** : Impossible de mesurer objectivement la qualité du code ni son évolution dans le temps.

## Pourquoi dans notre pipeline CI/CD ?

En intégrant SonarQube dans notre pipeline Jenkins :
- L'analyse est **automatique** à chaque push
- Les problèmes sont détectés **avant** le déploiement
- L'équipe a une **visibilité** en temps réel sur la qualité
- On peut définir des **Quality Gates** qui bloquent le déploiement si le code ne respecte pas les standards

## Le besoin

> Comment garantir la qualité, la sécurité et la maintenabilité du code de manière continue et automatisée ?

**Réponse : SonarQube** — un outil d'analyse statique de code intégré dans notre chaîne CI/CD.
