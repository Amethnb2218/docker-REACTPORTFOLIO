# 4.6. Démo — Pratique sur les concepts / Intégration dans le projet fil rouge

## Objectif de la démo

Intégrer SonarQube dans notre pipeline CI/CD Jenkins pour analyser automatiquement le code du portfolio React + Express à chaque push.

## Étape 1 : Lancement de l'environnement complet

```bash
# Lancer SonarQube + PostgreSQL
docker compose -f docker-compose.sonarqube.yml up -d

# Vérifier que SonarQube est prêt (attendre ~2 min)
curl -s http://localhost:9000/api/system/status | grep -o '"status":"[^"]*"'
# Résultat attendu : "status":"UP"
```

## Étape 2 : Configuration initiale de SonarQube

1. Ouvrir **http://localhost:9000**
2. Se connecter : `admin` / `admin` → changer le mot de passe
3. Créer un projet :
   - Project key : `portfolio-react-express`
   - Display name : `Portfolio React Express`
4. Générer un token : `squ_xxxxxxxxxxxx`

## Étape 3 : Exécution de l'analyse

```bash
# Depuis la racine du projet REACTPORTFOLIO
docker run --rm \
  --network sonarqube-net \
  -v "$(pwd):/usr/src" \
  sonarsource/sonar-scanner-cli \
  -Dsonar.projectKey=portfolio-react-express \
  -Dsonar.sources=/usr/src/reactportfolio/src,/usr/src/"EXPRESSJS PORTFOLIO"/src \
  -Dsonar.host.url=http://sonarqube:9000 \
  -Dsonar.token=squ_VOTRE_TOKEN
```

## Étape 4 : Lecture des résultats dans l'interface

### Dashboard principal
- **Bugs** : Nombre de bugs détectés (objectif : 0)
- **Vulnerabilities** : Failles de sécurité (objectif : 0)
- **Code Smells** : Problèmes de maintenabilité
- **Coverage** : Couverture de tests (objectif : > 80%)
- **Duplications** : Code dupliqué (objectif : < 3%)

### Exemples de problèmes détectés sur notre projet

| Type | Exemple | Fichier | Sévérité |
|------|---------|---------|----------|
| Bug | Variable utilisée avant assignation | `app.js` | Major |
| Code Smell | Fonction avec trop de paramètres | `src/routes.js` | Minor |
| Vulnerability | CORS trop permissif (`origin: *`) | `app.js` | Critical |
| Security Hotspot | Utilisation de `eval()` ou `innerHTML` | `src/components/` | High |

## Étape 5 : Quality Gate en action

### Configuration du Quality Gate "Sonar Way" :
- Couverture du nouveau code ≥ 80%
- Ratio de duplication du nouveau code ≤ 3%
- 0 nouvelles issues de fiabilité (bugs)
- 0 nouvelles vulnérabilités

### Scénario : Pipeline bloqué

```
Jenkins Pipeline:
✅ Checkout
✅ Install Dependencies
✅ Tests
✅ Build Frontend
✅ SonarQube Analysis
❌ Quality Gate → FAILED (2 nouveaux bugs détectés)
⏹ Docker Build (non exécuté)
⏹ Deploy (non exécuté)

📧 Email envoyé : "Build ÉCHOUÉ - Quality Gate non satisfait"
```

## Étape 6 : Correction et re-analyse

```javascript
// AVANT (bug détecté par SonarQube)
app.use(cors({ origin: '*' }));

// APRÈS (correction)
app.use(cors({ origin: process.env.ALLOWED_ORIGINS || 'http://localhost:3000' }));
```

Après correction et push :
```
Jenkins Pipeline:
✅ Checkout
✅ Install Dependencies
✅ Tests
✅ Build Frontend
✅ SonarQube Analysis
✅ Quality Gate → PASSED
✅ Docker Build
✅ Deploy
📧 Email envoyé : "Build RÉUSSI"
```

## Étape 7 : Suivi de l'évolution

Dans SonarQube > Activity :
- Graphiques d'évolution de la dette technique
- Historique des Quality Gates
- Tendance des bugs/vulnérabilités au fil des commits

## Commandes utiles

```bash
# Voir les logs SonarQube
docker logs sonarqube -f

# Redémarrer SonarQube
docker compose -f docker-compose.sonarqube.yml restart sonarqube

# Vérifier l'état via API
curl http://localhost:9000/api/system/health

# Lister les projets analysés
curl -u admin:password http://localhost:9000/api/projects/search
```
