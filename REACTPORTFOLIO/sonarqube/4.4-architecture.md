## Composants principaux

### 1. SonarQube Scanner (Client)

Le scanner s'exécute côté CI/CD (Jenkins) et :
- Analyse le code source
- Collecte les métriques
- Envoie les résultats au serveur SonarQube

### 2. SonarQube Server

Le serveur comprend 3 processus :

| Processus | Rôle |
|-----------|------|
| **Web Server** | Interface utilisateur, API REST, gestion des configurations |
| **Compute Engine (CE)** | Traite les rapports d'analyse et met à jour la base de données |
| **Elasticsearch** | Indexe les données pour la recherche dans l'interface |

### 3. Base de données

PostgreSQL stocke :
- La configuration (profils, règles, quality gates)
- Les snapshots et historiques
- Les issues et leurs états

## Flux d'analyse

1. **Push** sur GitHub → webhook déclenche Jenkins
2. **Jenkins** exécute le pipeline → étape SonarQube Scanner
3. **Scanner** analyse le code et envoie le rapport au serveur
4. **Compute Engine** traite le rapport
5. **Quality Gate** évalue les résultats
6. **Webhook SonarQube** notifie Jenkins du résultat (pass/fail)
7. **Jenkins** continue ou bloque le déploiement selon le résultat
