# 4.3. Concepts SonarQube

## Bug

Un **bug** est une erreur dans le code qui produit un comportement incorrect ou inattendu à l'exécution.

**Exemple** : Utiliser `==` au lieu de `===` en JavaScript peut provoquer des comparaisons inattendues.

```javascript
// Bug : comparaison non stricte
if (value == null) { ... }
// Correct
if (value === null) { ... }
```

## Code Smell

Un **code smell** est un problème de maintenabilité. Le code fonctionne, mais il est difficile à comprendre, modifier ou étendre.

**Exemple** : Fonction trop longue, variable mal nommée, code dupliqué.

## Remediation Cost (Coût de remédiation)

Le **coût de remédiation** est le temps estimé nécessaire pour corriger un problème. SonarQube l'exprime en minutes/heures/jours.

- Bug simple : ~5 min
- Refactoring complexe : ~2h
- Vulnérabilité critique : ~4h

## Technical Debt (Dette technique)

La **dette technique** est la somme de tous les coûts de remédiation. Elle représente l'effort total nécessaire pour rendre le code conforme aux standards de qualité.

> Si la dette technique = 5 jours → il faudrait 5 jours de travail pour corriger tous les problèmes.

## Issue

Une **issue** est un problème détecté par SonarQube. Chaque issue a :
- Un **type** : Bug, Vulnerability, Code Smell
- Une **sévérité** : Blocker, Critical, Major, Minor, Info
- Un **coût de remédiation**
- Une **localisation** : fichier + ligne

## Measure (Mesure)

Une **mesure** est une valeur brute collectée sur le code :
- Nombre de lignes de code (LOC)
- Nombre de bugs
- Nombre de fichiers
- Temps de dette technique

## Metric (Métrique)

Une **métrique** est un indicateur calculé à partir des mesures :
- **Couverture de tests** : % du code couvert par les tests
- **Densité de duplication** : % de code dupliqué
- **Ratio de dette technique** : dette / temps de développement

## New Code Period (Nouveau code)

Le **nouveau code** est le code ajouté ou modifié depuis une référence (branche, version, date). SonarQube se concentre sur le nouveau code pour garantir que la qualité s'améliore progressivement ("Clean as You Code").

## Quality Profile (Profil de qualité)

Un **profil de qualité** est un ensemble de règles activées pour un langage donné. Par défaut, SonarQube fournit le profil "Sonar Way" pour chaque langage.

## Rule (Règle)

Une **règle** est un critère d'analyse spécifique. Chaque règle détecte un pattern problématique.

**Exemple de règle JavaScript** : "Functions should not have too many parameters" (max 7 paramètres).

## Quality Gate

Un **Quality Gate** est un ensemble de conditions que le code doit satisfaire. Si une condition échoue, le gate est en état "Failed" et peut bloquer le pipeline.

Conditions typiques :
- Couverture du nouveau code > 80%
- 0 nouvelles vulnérabilités
- Densité de duplication < 3%

## Snapshot

Un **snapshot** est une capture de l'état de la qualité du code à un instant donné. Chaque analyse crée un snapshot qui permet de suivre l'évolution dans le temps.

## Security Hotspot

Un **security hotspot** est un morceau de code sensible du point de vue sécurité qui nécessite une revue manuelle. Ce n'est pas forcément une vulnérabilité, mais ça pourrait en être une.

**Exemple** : Utilisation de `eval()`, configuration CORS permissive, stockage de données sensibles.

## Vulnerability (Vulnérabilité)

Une **vulnérabilité** est une faille de sécurité confirmée dans le code qui peut être exploitée par un attaquant.

**Exemples** :
- Injection SQL
- Cross-Site Scripting (XSS)
- Hardcoded credentials
- Path traversal
